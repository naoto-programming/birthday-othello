# 誕生日オセロ 設計仕様

作成日: 2026-10-29

## 1. 目的と前提

家族5人(中学生1人・高校生2人・大人2人)が全員誕生日を迎えたことにちなんだ、家族へのプレゼントとしてのゲーム。
家族が集まったときに、1台の端末(PCまたはスマートフォン)を2人で交代に操作して1対1で対戦する。

オセロと「日付の綱引き」を組み合わせた戦略ゲーム。2人が1つの日付を反対方向へ引っ張り合い、自分の誕生日にぴったり止めた方が勝つ。

## 2. 対戦前の設定

### 入力項目

- プレイヤー2人分の名前と誕生日(月・日)。家族の誕生日は登録せず、毎回入力する。
- 開始日(年月日)。2人の誕生日が入力されると、既定の開始日が自動で入る。変更もできる。

### 年の扱い

- 基準年 Y は、設定時点での端末の現在の年とする。
- 誕生日は月日のみを持ち、日付の範囲に現れる各年の実際の日付として扱う。
- 2/29生まれの人の誕生日は、うるう年でない年では2/28として扱う。

### 黒白の決定

- 開始日 S の前日から過去へ1日ずつさかのぼり、最初に出てくる誕生日の人が**黒**になる。その日付を「黒の誕生日」とする。
- 開始日 S の翌日から未来へ1日ずつ進み、最初に出てくる誕生日の人が**白**になる。その日付を「白の誕生日」とする。
- 2人が同じ誕生日の場合は、さかのぼって最初に出てくる誕生日を黒の誕生日、進んで最初に出てくる誕生日を白の誕生日とし、黒白はランダムに決める。この場合、日付の範囲は約1年になる。
- 開始日がどちらかの誕生日と同じ日の場合は開始できない。その旨のメッセージを出す。

### 日付の範囲と内部表現

- D = 黒の誕生日から白の誕生日までの日数。
- 現在の日付は、位置 p(0 ≦ p ≦ D、黒の誕生日から何日目か)として持つ。現在の日付 = 黒の誕生日 + p 日。
- p = 0 は黒の誕生日、p = D は白の誕生日を表す。

### 既定の開始日

- 2人の誕生日の間のうち、間隔が短い側の真ん中の日にする。年末年始をまたぐ場合は、またいだ側で数える。
- 割り切れない場合は白の誕生日寄りにする。先手の黒に対し、後手の白へ1日ゆずるため。
- 間隔が短い側が1日以下(連続した誕生日や同じ誕生日)で、間に日がない場合は、長い側の真ん中を使う。

### 確認表示

入力に応じて、次のような確認文を表示する。

> 黒: たろう(10/14) 白: はなこ(12/3) 間は50日、石の増え方は+2

## 3. 基本ルール

### 盤面と手番

- 8×8の盤面。初期配置は通常のオセロと同じ中央4石(石の重さはすべて初期状態)。
- 先手は黒。以後は交互に打つ(「もう一手」の効果を除く)。
- 空いているマスならどこにでも置ける。パスはない。

### 裏返し

- 置いた石から縦・横・斜めの8方向について、通常のオセロと同様に、相手の石を挟んでいれば挟まれた石をすべて裏返す。
- **固定された石**(イベント「固定」によるもの)は裏返らない。相手の固定石が方向の途中にある場合、その方向は挟めない(壁として働く)。自分の固定石は、挟む端として通常どおり使える。

### 石の重さ

- 各石は「これまでに裏返った回数」k を持つ。新しく置いた石は k = 0。
- 石の重さ = 1 + k × s。重さは「次に裏返ったときに日付を何日動かすか」を表し、石の上に数字で表示する。
- 増え方 s = max(1, round(D / 24))。例: D=20 なら s=1、D=40 なら s=2、D=180 なら s=8。
- 裏返ったとき、その時点の重さ分だけ日付が動き、その後 k が1増える。

### 日付の移動

1. 基本の移動日数 = その手で裏返った石の重さの合計。
2. 1枚も裏返らなかった場合、日付は動かない。この場合も、その手に効く予定だった効果はすべて使い切ったものとする。
3. 移動の向き: 黒の手は過去へ(p が減る)、白の手は未来へ(p が増える)。
4. 跳ね返り: p が 0 を下回ったら、下回った分だけ反対へ跳ね返る(p → −p)。p が D を上回ったら、上回った分だけ跳ね返る(p → 2D − p)。範囲に収まるまで繰り返す。
5. 移動はアニメーションで1日ずつ数えるように見せる。移動日数が多い場合も、演出は最大1.5秒程度に収める。

例: 黒の誕生日が10/14、現在が10/16(p=2)のとき、黒が合計5日分を裏返すと、10/14で3日分跳ね返って10/17(p=3)になる。

### 勝敗

- 移動後に p = 0 になったら黒の勝ち、p = D になったら白の勝ち。どちらが動かしたかは関係ない。
- 手番の開始時、または打った後に空きマスがなくなったら終局する。そのときは、自分の誕生日までの残り日数(黒は p、白は D − p)が少ない方の勝ち。同じなら石の数が多い方の勝ち。それも同じなら引き分け。
- 誕生日でのぴったり決着は、イベントの発動より優先する。

### 1手の処理順

1. 石を置き、挟んだ石を裏返す。
2. 移動日数を計算し(4章の計算順)、日付を動かす(跳ね返りを含む)。
3. 誕生日でのぴったり決着を判定する。決着したら終局。
4. イベントの発動を判定し、発動したら効果を処理する(石やマスの選択を含む)。
5. 空きマスがなければ、盤面が埋まったときの判定で終局。
6. 次の手番へ(「もう一手」なら同じ人がもう一度打つ)。

## 4. イベント

### 発動のルール

- 石を打って日付が動き、移動後の日付がイベントの日にぴったり一致したら、打った人に発動する。途中で通過しただけでは発動しない。
- 同じイベント(同じ実際の日付)は1試合に1回だけ発動する。発動済みのイベントは盤面上で薄く表示する。
- 開始日がイベントの日でも発動しない。日付が動かなかった手でも発動しない。
- 「真ん中へ」で移動した先がイベントの日でも発動しない(連鎖なし)。
- 石を選ぶ効果・空きマスを選ぶ効果で、選べる対象がない場合は不発になる。

### 次の手に効く効果の計算順

「自分の次の手」は、その人が次に石を置く手(「もう一手」による連続手番を含む)を指す。「相手の次の手」は、相手が次に石を置く手を指す。
複数の効果が同じ手に重なった場合は、次の順に計算する。

1. 基本の移動日数(重さの合計)
2. 日数2倍
3. 日数プラス(+3日)
4. 日数調整(−3〜+3日から本人が選ぶ。結果は0日未満にならない)
5. おやすみ(移動日数を0にする)
6. うそ(移動の向きを逆にする)

### 効果の種類(12種類)

| ID | 名前 | 内容 |
|---|---|---|
| plus3 | 日数プラス | 自分の次の手で動く日数が+3日 |
| double | 日数2倍 | 自分の次の手で動く日数が2倍 |
| adjust | 日数調整 | 自分の次の手で、動く日数を−3〜+3日の範囲で選べる |
| extraTurn | もう一手 | 続けてもう1回打てる |
| rest | おやすみ | 相手の次の手は日付が動かない(石は普通に裏返る) |
| reverse | うそ | 相手の次の手は日付が逆向きに動く |
| middle | 真ん中へ | 日付が p = floor(D / 2) の位置へ飛ぶ |
| remove | 鬼は外 | 相手の固定されていない石を1つ選んで取り除く(空きマスになる) |
| fix | 固定 | 自分の固定されていない石を1つ選んで固定する。以後は裏返らず、イベントの対象にもならない |
| steal | 奪う | 相手の固定されていない石を1つ選んで自分の色にする(日付は動かず、重さも変わらない) |
| resetWeights | 重さリセット | 盤面のすべての石の裏返り回数を0に戻す(重さが1に戻る) |
| plant | 植える | 空きマスを1つ選び、自分の石を置く(何も裏返らず、日付も動かない。新しい石の重さは1) |

イベント一覧は、日付・名前・効果IDの表(データ)として events.js に持つ。イベントの追加や効果の入れ替えは、表の行を編集するだけで済むようにする。

### 祝日の日付計算

- 固定日の祝日・行事は表の日付のまま使う。
- 成人の日・海の日・敬老の日・スポーツの日は、その年の該当月の第N月曜日として計算する。
- 春分の日 = floor(20.8431 + 0.242194 × (年 − 1980) − floor((年 − 1980) / 4)) 日(3月)。
- 秋分の日 = floor(23.2488 + 0.242194 × (年 − 1980) − floor((年 − 1980) / 4)) 日(9月)。
- 上の2式は1980〜2099年で使える近似式。
- 振替休日と国民の休日は、名前のある祝日ではないためイベントに含めない。
- 日付の範囲が年をまたぐ場合は、範囲内の各年について計算する。

## 5. 画面

### 設定画面

- 2人分の名前入力、誕生日の月・日の選択、開始日の入力。
- 2章の確認文と、開始できない場合のメッセージを表示する。
- 「対戦開始」ボタン。

### 対戦画面

- **上部の帯:** 現在の日付(大きく)、手番、2人の名前・誕生日・残り日数、次の手に効く効果(例: 「ハロウィン: 次の手2倍」)。
- **カレンダー風の盤面:**
  - 各マスの隅に、現在の日付がある月の1日から数えて64日分の日付を、左上から右へ・上から下へ順に小さく印刷する。月が変わるマスには月も書く(例: 12/1)。
  - 現在の日付・イベントの日・黒の誕生日・白の誕生日のマスは色分けする。この色分けは飾りで、そのマスに石を置いても効果はない。
  - 日付が別の月へ動いたら、印刷する日付も切り替える。
  - 石の上に重さの数字を表示する。固定石は見た目で区別する。
- **打った後の演出:** 石の裏返り、日付が1日ずつ数えるように動く演出、跳ね返りの表示。
- **イベント発動時:** イベント名と効果をポップアップで表示する。石やマスを選ぶ効果では、選べるマスを強調し、盤面をタップして選ぶ。日数調整は −3〜+3 のボタンで選び、決定する。
- **ルールボタン:** ルールの要約とイベント一覧を表示する。

### 結果画面

- 勝者の名前で「お誕生日おめでとう、◯◯!」を、ケーキと紙吹雪の演出付きで表示する。
- 決着の仕方(誕生日にぴったり到達、または盤面が埋まったときの判定)を表示する。引き分けの場合はその旨を表示する。
- 「同じ2人で再戦」と「設定に戻る」のボタン。

### 対応端末

- スマートフォン縦向き: 盤面を画面幅いっぱいに表示する(左右に16pxの余白)。幅約320pxで1マス40px程度。タップで操作する。
- PC: クリックで操作する。
- ページ全体が横にスクロールしないようにする。

## 6. 対象外

コンピューター対戦、通信対戦、待った、途中保存(再読み込みすると対戦は最初から)、効果音、家族の誕生日の登録。

## 7. 構成

フレームワークやビルド手順を使わず、HTML・CSS・JavaScript(ESモジュール)で作る。

```
birthday-othello/
  index.html
  css/style.css
  js/
    dates.js      日付の計算(日付を通し番号で扱う処理、黒白と範囲の決定、既定の開始日、盤面に印刷する64日分)
    holidays.js   その年の祝日・行事の日付
    events.js     イベント一覧の表と効果の説明文
    rules.js      ルール本体(盤面、裏返し、重さ、日付の移動、跳ね返り、勝敗、効果の適用)
    ui.js         画面の表示と入力の受け付け
    main.js       起動と画面の切り替え
  tests/
    dates.test.js
    holidays.test.js
    rules.test.js
  package.json    "type": "module" と、テスト実行用の設定。依存パッケージなし。
```

- rules.js・dates.js・holidays.js・events.js は画面(DOM)に触れない純粋な処理だけにする。
- 日付はタイムゾーンの影響を避けるため、UTC基準の通し番号(1970-01-01からの日数)で扱う。
- ゲームの状態は1つのオブジェクトで持ち、rules.js の関数は状態を受け取って次の状態を返す。

## 8. テスト

Node.js の標準テスト機能(`node --test`)で、純粋な処理を自動テストする。ルール部分はテストを先に書いてから実装する。

主なテスト項目:

- 1章の例(10/16から5日分で10/17)を含む、両端での跳ね返り。
- 移動日数が大きい場合の複数回の跳ね返り。
- どちらが動かしても、止まった誕生日の人が勝つこと。
- 石の重さと増え方 s の計算。
- 固定石が裏返らないことと、相手の固定石が壁になること。
- 効果が重なったときの計算順。
- 裏返しなしの手では日付が動かず、効果が使い切られること。
- 盤面が埋まったときの判定(残り日数、石の数、引き分け)。
- 年またぎ、2/29生まれ、同じ誕生日の2人、連続した誕生日の黒白決定と既定の開始日。
- 2026年の祝日の日付を、内閣府が公開している祝日一覧と照合する。

画面は、ブラウザで実際に遊んで確認する。スマートフォン幅の表示も確認する。

## 10. 設計時の検証の記録

ルールを決めるために、使い捨てのシミュレーションで「誕生日に届いて決着する割合」を調べた。AIには、6割は自分の誕生日に最も近づく手を、4割は適当な手を打たせ、各200局を対戦させた。開始日は真ん中に置いた。

| 開始日から誕生日まで(片側) | 石の重さ一定 | +1ずつ | 距離に合わせて(採用) | 2倍ずつ |
|---|---|---|---|---|
| 5日 | 約80〜100% | 100% | 100% | 100% |
| 10日 | 約30〜60% | 100% | 100% | 100% |
| 20日 | 約1〜4% | 81% | 96% | 94% |
| 45日 | 0% | 8% | 64% | 74% |
| 90日 | 0% | 0% | 41% | 46% |

- 「石の重さ一定」の列だけは、別の条件で調べた値。毎回最善手だけを打つAI同士と、完全に適当に打つAI同士の結果を幅で示している。
- 石の重さが一定だと、2人が引き合って日付が行き来するため、片側15日を超えるとほとんど決着しない。
- 採用した「距離に合わせて」(s = round(D / 24))でも、誕生日が半年近く離れた2人では約6割が盤面が埋まったときの判定で決まる。
- 先手の黒が有利かどうかも調べた。毎回最善手だけを打つAI同士では、黒が約1.5倍多く勝った。一方、適当な手が混じる場合はほぼ5分5分だった。このため、先手と後手の調整は既定の開始日の端数を白寄りにするだけにとどめた。
