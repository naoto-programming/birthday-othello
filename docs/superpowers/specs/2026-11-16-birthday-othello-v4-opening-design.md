# 誕生日オセロ v4 設計仕様(序盤の駆け引き)

作成日: 2026-11-16
前の仕様: `docs/superpowers/specs/2026-11-11-birthday-othello-v3-design.md`(この文書に書いていない点は v3 → v2 → v1 のまま)

## 1. 目的

v3 では空の盤面から始まるため、最初の数手は挟める石がなく、日付も動かない。どこに置いても同じで、戦略も駆け引きもない(AI 同士の対戦で、日付が初めて動くのは平均7手目)。

ユーザーの要望: 置ける場所に制限をつけたり特殊な要素を足したりして、最初から心理戦に持ち込みたい。ユーザーが選んだ形は次の2つの組み合わせ。

- 開始時に、黒白2個ずつの石をランダムな位置に置く(周り8マスにほかの石がない位置)。
- 最初の何ターンかは、自分の色の石の周り8マスには置けない。その後は置ける。

### 判断の経緯(シミュレーション、2026-11-15〜16)

ていねいな AI(1手先を読む)同士で各400局。安定して測れた指標は次の2つ。

| 序盤の形 | 日付が初めて動く手 | 序盤の1手で選べる結果(日付)の種類 |
|---|---|---|
| 今(空の盤面) | 7.2手目 | 1.3 |
| 最初の石だけ | 4.5手目 | 1.6 |
| 最初の石 + 最初の3ターンは自分の石の周りに置けない(この仕様) | 4.3手目 | 1.5 |
| 最初の石 + 最初の3ターンは相手の石の周りにだけ置ける(提案した別案) | 2.3手目 | 1.9 |

ユーザーには、AI では「この仕様」と「最初の石だけ」の差がほとんど見えないこと、AI は1手先しか読めず人同士の駆け引きは測れないことを伝えたうえで、「この仕様」が選ばれた。どの形でも先手の勝率は 50〜54%、最後の判定は 0%。

## 2. ルールの変更

### 2.1 最初の石

- 対戦の開始時(再戦も含む)に、黒2個・白2個の石を盤面(8×8)にランダムに置く。
- 置く位置の条件: その石の周り8マス(縦・横・斜めに隣り合うマス)に、ほかの最初の石がない。盤面の端や角でもよい。
- 最初の石は普通の石と同じ(重さ1、固定されていない)。
- 置く順番と色: 黒・白・黒・白の順に1個ずつ、条件を満たすマスから等しい確率で選ぶ。
- 盤面のマスに印刷された日付・今日・誕生日・行事は、マスの見た目の印にすぎない(v3 と同じ)。最初の石はどのマスに置かれてもよく、置かれたマスは普通の「石のあるマス」になる。日付の位置は盤面のマスではなく日付の道の上の数(v3 の `p`)なので、石とは関係しない。
- 日付の位置(開始マス)、イベント、手番(黒から)は v3 のまま。

### 2.2 最初の3ターンの制限

- v3 では、空いているマスならどこにでも置ける(挟めなくてもよい)。v4 の制限は、この「置けるマス」から一部を外すもの。
- 黒も白も、自分の最初の3手では、自分の色の石の周り8マスには置けない。
  - 「手」は、手番でマスをタップして石を置く通常の手(v3 の `playMove`)だけ。効果で石を置いたり変えたりしても(植える・奪う・固定・鬼は外)、手の数には入らない。このゲームにパスはない。(コントローラーの判断)
  - 「自分の色の石」は、置こうとする時点の盤面にある自分の色の石すべて(最初の石、自分で置いた石、裏返したり奪ったりして自分の色になった石、固定された石)。
  - 相手の石の周りや、どの石からも離れたマスには置ける。
- 4手目からは、空いているマスならどこにでも置ける(v3 のまま)。
- 置けるマスが1つもないときは、その手に限り、空いているマスならどこにでも置ける。(コントローラーの判断)
- 「もう一手」で続けて打つ手も、1手として数える。(コントローラーの判断)
- 次の効果は、この制限を受けない(v3 のまま)。(コントローラーの判断)
  - 植える(空いているマスを選んで石を置く)
  - 奪う
  - 固定
  - 鬼は外
- 様子見の代償(挟める手があるのに1枚も返さない手は、相手の誕生日の方へ1マス)は、「この手で置けるマス」のうち挟めるマスがあるときだけ働く。置けないマスでしか挟めないなら、代償はない。(コントローラーの判断: 置けない手を打たなかったことで罰を受けないように)
- サドンデス(盤面が広がったあと)には、この制限は関係しない(盤面が埋まるのは4手目よりずっと後のため)。

## 3. 画面の変更

- 最初の石は、対戦画面を開いたときから盤面に出ている。開始時に、4つの石が順に落ちてくる短い演出(合計約0.8秒、動きを減らす設定ではなし)。
- 制限のある手番では:
  - 置けないマスに印を付ける。例: 薄い灰色の斜線。空きマスだけに付け、今日の金色の枠や誕生日・行事の色と見分けられること。
  - 手番の文(「たろう(黒)の番です」)のすぐ下の1行に、残りを出す: 「自分の石の周りには置けません(あと2ターン)」。
  - 置けないマスをタップしたら、置かずに、その行を目立つ色の注意「自分の石の周りには置けません」に変える。次の描画で元に戻る。
  - この行は、どちらかの人に制限が残っている間はずっと場所を取る(演出中は空にして場所だけ取る)。こうすると、打つときや置けないマスをタップしたときに盤面が上下に動かない。両方の制限が終わったら、行を閉じる(盤面が動くのは1試合に1回だけ)。(コントローラーの判断、2026-11-18 の最終レビューで、手番の文が2行になって演出のたびに盤面が上下する、注意で盤面が下にずれて押し間違える、という問題が見つかったため)
- 4手目からは、印も注意も出ない。
- 置けるマスが1つもなくて、どこにでも置ける手番(2.2 の例外)では、印を付けず、その行は「置ける場所がないので、どこにでも置けます」にする。(コントローラーの判断)
- ルール画面に次を足す:
  - 「最初に黒白2個ずつの石が、ランダムな場所に置かれます。」
  - 「最初の3ターンは、自分の石の周り8マスには置けません。」
- 設定画面の説明文は変えない。

## 4. テストのための入口

スモークテストが決まった盤面で操作できるように、URL の問い合わせ文字列で次を受け付ける(画面からはたどれない、テスト用)。(コントローラーの判断)

- `?seed=<整数>`: 最初の石の位置を、この値から決まる乱数で選ぶ。同じ値なら同じ配置になる。
- `?opening=off`: 最初の石を置かず、3ターンの制限もない(v3 と同じ始まり方)。既存のスモークテストのシナリオは、これを付けて今のまま動かす。

ルールの処理(js/rules.js)は、乱数の元と「序盤の仕組みを使うか」を引数で受け取り、ブラウザや URL には触れない。

## 5. テストとバランス

- 単体テスト:
  - 最初の石の配置: 4個、黒2・白2、どの石の周り8マスにもほかの石がない、同じ乱数なら同じ配置。
  - 3ターンの制限:
    - 自分の石の周りには置けない
    - 相手の石の周りには置ける
    - 4手目から置ける
    - 置けるマスがないときはどこでも
    - もう一手も1手と数える
  - 様子見の代償は、置けるマスだけで判断する。
  - 序盤の仕組みを使わない設定(`opening=off` に当たるもの)では v3 と同じ。
- スモークテスト:
  - 新しいシナリオ: `?seed=` で決まった配置になる。最初の石が4個ある。置けないマスに印がある。置けないマスをタップしても置かれず注意が出る。3ターン後に印が消えて置ける。
  - 既存のシナリオは `?opening=off` で今のまま通る。
- バランス確認(`npm run balance`)は序盤の仕組みを使って対局し、v3 の合格条件(未決着0、最後の判定 10% 以下)を満たすこと。先手の勝率も表示する(参考値)。

## 6. 対象外

v3 と同じ(コンピューター対戦、通信対戦、待った、途中保存、効果音、家族の誕生日の登録)。制限のターン数を設定画面で変えることもしない。
