# 誕生日オセロ v2 設計仕様

作成日: 2026-11-07
元の仕様: `docs/superpowers/specs/2026-10-29-birthday-othello-design.md`(この文書に書いていない点は元の仕様のまま)

## 1. 目的

公開版を遊んだうえでの要望に応える。

1. 最初から真ん中に4つの石があると普通のオセロになってしまうので、無くす。
2. 今どの日付にいるかが分かりにくいので、分かりやすくする。
3. 単純すぎて面白くないので、頭脳戦としてのゲーム性を持たせる。要素はあまり増やさず、AI同士の対戦で確かめて決める。
4. アニメーションを増やす。

## 2. ルールの変更

### 2.1 盤面と置き方

- 盤面は空の状態から始める。先手は黒。最初の1手はどのマスにも置ける。
- 空いているマスならどこにでも置ける(変更なし)。

### 2.2 返す列を選べる

- 「列」とは、置いたマスから見た1つの方向で、相手の石が連続し、その先に自分の石があるもの。相手の固定石は今まで通り壁になり、その方向は列にならない。自分の固定石は端として使える。
- 置いたマスに列が1つ以上あるときは、返す列を1つ以上選ぶ。選んだ列の石だけが裏返る。
- 列が1つ以上あるマスに置くとき、どの列も返さないことはできない(少なくとも1列)。

### 2.3 日付の道(マス)

- D = 黒の誕生日から白の誕生日までの日数(変更なし)。
- マス数 N と1マスの日数 k:
  - D ≦ 30 のとき、N = D、k = 1(1マス = 1日。今まで通り)。
  - D > 30 のとき、k = ceil(D ÷ 30)、N = round(D ÷ k)。N は30以下になる。
  - 例: D = 50 → k = 2、N = 25。D = 180 → k = 6、N = 30。D = 365 → k = 13、N = 28。
- 位置 p は0〜Nのマス番号で持つ。p = 0 は黒の誕生日、p = N は白の誕生日。
- マス u の日付 = 黒の誕生日 + round(u × D ÷ N)。マス0は黒の誕生日、マスNは白の誕生日になる。
- 日付 d が属するマス = round((d − 黒の誕生日) × N ÷ D)。マス u が受け持つ期間は、属するマスが u になる日付の集まり。
- round は四捨五入(0.5は切り上げ)。

### 2.4 石の重さ

- 石の重さ = 1 + その石がこれまでに裏返った回数。
- 元の仕様の増え方 s は削除する。日付の道が30マス以下になったことで、元の式 max(1, round(N ÷ 24)) は常に1になるため。

### 2.5 日付の動き方

1. 1枚以上裏返したとき:
   - 基本の移動マス数 = 裏返した石の重さの合計。
   - 効果の計算順は元の仕様の通り(2倍 → +3 → 調整 → おやすみ → うそ)。すべてマス単位で数える。
   - 黒は p を減らす向き、白は p を増やす向きに動かす。
2. 1枚も裏返さなかったとき(様子見の代償):
   - 日付は相手の誕生日の方へ1マス動く。黒は p + 1、白は p − 1。
   - 2倍・+3・調整・おやすみ・うそは関係しない。予定されていた効果は使い切る(元の仕様と同じ)。
3. どちらの場合も、範囲を出たら跳ね返る(元の仕様と同じ。0とNで反射し、範囲に収まるまで繰り返す)。
4. 移動後に p = 0 なら黒の勝ち、p = N なら白の勝ち。誰が動かしたかは関係ない。様子見の代償で相手の誕生日に止まった場合は、相手の勝ち。

### 2.6 開始位置

- 開始日の決め方は元の仕様のまま(既定は間隔が短い側の真ん中で、端数は白寄り。変更もできる)。
- 開始マス = 開始日が属するマス。ただし1〜N−1の範囲に収める。

### 2.7 イベント

- 黒の誕生日から白の誕生日までの間(両端を除く)にある各イベントは、その日付が属するマスに割り当てる。1つのマスに複数のイベントが入る場合は、日付が早いものだけを使う。マス0とマスNに入るイベントは使わない。
- 石を打って日付が動き、移動後のマスにイベントがあれば、打った人に発動する。様子見の代償で動いた場合も同じ。日付が動かなかった手では発動しない。1試合に1回だけ発動する(元の仕様と同じ)。
- 効果はマス単位で働く:
  - 日数プラス → 次の手で動くマス数 +3
  - 日数調整 → −3〜+3マス
  - 真ん中へ → p = floor(N ÷ 2)
- 効果の説明文は「日」を「マス」に置き換える。
  - 例: 「自分の次の手で動くマス数が+3」「自分の次の手で、動くマス数を−3〜+3の範囲で選べる」「日付が2人の誕生日のちょうど真ん中のマスに飛ぶ」。

### 2.8 勝敗(盤面が埋まったとき)

- 元の仕様のまま。ただし残りはマス数で比べる(黒は p、白は N − p)。

## 3. 画面の変更

### 3.1 設定画面

- 確認文の形式:
  - D > 30 の例: 「黒: たろう(10/14) 白: はなこ(12/3) 間は50日、25マス(1マス=2日)」
  - D ≦ 30 の例: 「黒: … 白: … 間は20日(1マス=1日)」
- 1マスの日数の表示: D ÷ N が割り切れるときは「1マス=k日」、割り切れないときは「1マス=約k日」。表示する k は D ÷ N の四捨五入。

### 3.2 上部の帯

- 今日の日付(大きく)の表示は変更なし。
- D > 30 のときは、今日の日付の近くに「1マス=(約)k日」を小さく表示する。
- 残りの表示:
  - k = 1 のとき: 「あと◯日」。
  - k > 1 のとき: 「あと◯マス(約◯日)」。日数は今日の日付と各自の誕生日の実際の日付の差。

### 3.3 カレンダー盤面の今日の強調

- 今日のマス(今日の日付のセル)の強調:
  - 太い金色の枠
  - ゆっくり脈打つ光
  - 「今日」の小さな札
- k > 1 のときは、今のマスが受け持つ期間の日付セルにも薄い色をつける。
- マスの日付、イベント・誕生日の色分けは今のまま。

### 3.4 打つ流れ(予告 → 決定)

1. 空きマスをタップすると予告になる(まだ打たれない):
   - タップしたマスに半透明の石を出す。
   - 返る石を光らせる。列が複数あるときは、各列を枠で示す。返す列は実線、返さない列は点線。
   - 列の中の石をタップすると、その列の返す/返さないを切り替える。最後の1列は外せない。
   - 盤面の下の予告パネルに「◯マス動く → ◯月◯日」を出し、行き先の日付セルを点滅させる。
   - 1枚も返らない手では「返さない: 相手側へ1マス → ◯月◯日」と出す。
   - 行き先が誕生日なら「◯◯の誕生日にぴったり!」、イベントのマスなら「◯◯(イベント名)」も出す。
   - 日数調整の効果があるときは、予告パネルに −3〜+3 のボタンを出す(初期値0)。表示する行き先も選んだ値に合わせて変わる。
2. 「ここに置く」ボタン、または同じマスをもう一度タップすると決定する。
3. 「やめる」ボタンで予告を取り消す。別の空きマスをタップすると、そのマスの予告に切り替わる。

予告中も上部の帯や盤面の表示は現在の状態のままで、決定するまで何も変わらない。

### 3.5 ルール画面

ルールの要約を新しいルールに合わせて書き換える。追加・変更する内容:
- 空の盤面から始まる。
- 返す列を選べる。
- 日付の道とマス(1マスの日数)。
- 石の重さは「1 + 裏返った回数」。
- 様子見の代償。
- 予告 → 決定の流れ。

## 4. アニメーション

全体の方針:
- 端末の「視差効果を減らす(動きを減らす)」設定が有効なときは、動きを止めるか最小限にする。
- 日付が動く演出の合計は最大1.5秒程度(元の仕様と同じ)。

### 4.1 日付が動くとき

- 今日の光が、盤面のカレンダーの上を1マス(k日)ずつ移動する。
- 跳ね返るときは、誕生日のセルで光が弾むように縮んで戻り、「跳ね返り!」を表示する。
- 今日の日付が別の月に入るときは、カレンダーをページのようにめくってから続きを動かす。

### 4.2 石を置く・返すとき

- 置いた石は上から落ちて、着地で小さく弾む。
- 裏返る石は、置いたマスに近いものから順に1枚ずつ返る(約0.08秒ずつずらす)。
- 予告中、返せる列は順番に光り、半透明の石はゆっくり脈打つ。

### 4.3 イベントと手番交代

- イベントのポップアップは弾むように現れる。
- 効果が働いた石や名札が光る。
  - 固定: 金色の光
  - 奪う: 色が変わる裏返り
  - 植える: 落ちてくる
  - 鬼は外: 薄くなって消える
  - 次の手に効く効果: その人の名札が光る
- 手番が変わると、次に打つ人の名札が少し大きくなって光り、もう一方は小さく戻る。

### 4.4 勝利

- ケーキのろうそくの火が揺れる。
- 紙吹雪を増やす。
- 盤面上の勝った人の誕生日のセル(盤面に出ていなければ盤面の中央)から花火が上がる。

## 6. テスト

### 6.1 単体テスト(node --test)

- 空の盤面から始まる。
- 列の求め方:
  - 複数方向の列
  - 相手の固定石が壁になる
  - 自分の固定石を端に使える
- 返す列の選択:
  - 選んだ列だけが返る
  - 少なくとも1列が必要
  - 列のないマスでは返す石がない
- 日付の道:
  - D = 20、50、180、365、同じ誕生日の N と k
  - マス ↔ 日付の変換
  - マスの期間
  - 年またぎ
  - 開始マスを1〜N−1に収める
- 様子見の代償:
  - 黒は+1、白は−1
  - 効果は関係なく使い切る
  - 跳ね返る
  - 相手の誕生日に止まると相手の勝ち
  - イベントのマスなら発動する
- イベントのマス割り当て(同じマスに複数あれば早い方、両端は除く)。
- 効果がマス単位で働く(+3、調整、真ん中へ)。
- 予告用の関数と実際の手の結果が一致する。
- 盤面が埋まったときの判定(マス数)。

### 6.2 スモークテスト(ヘッドレスChrome、`caffeinate -i npm run smoke`)

これまでの確認項目はすべて残し、操作を「予告 → 決定」に合わせる。加えて次を確認する:
- 予告中は石が置かれず、決定で置かれる。
- 列の切り替えで、返る石と予告の日付が変わる。
- 「やめる」で取り消せる。
- 今日のマスに強調と「今日」の札がある。
- 動きを減らす設定で、決定から盤面の更新までがすぐ終わる。

### 6.3 バランス確認(`caffeinate -i npm run balance`)

- 実際の誕生日の組み合わせ(ランダム)と実際のイベントで、ていねいなAI同士を200局対戦させる。
  - ていねいなAI: 1手先で一番得な手を選び、相手にすぐ勝たれる手は避ける。
- 誕生日で決着した割合、平均手数、先手の勝率を表示する。
- 誕生日決着の割合が60〜90%の範囲にあれば合格とする(下の実験記録で約76%)。

## 7. 設計時の実験の記録

使い捨ての高速シミュレーターで調べた。シミュレーターは本物の rules.js と300局で一致することを確認している。AIは次の4種類:
- 適当なAI
- その場しのぎAI: 1手先だけを見る
- ていねいなAI: その場しのぎ + 相手にすぐ勝たれる手を避ける
- 強いAI: 2手先まで読む

初期の実験では乱数生成器が約1万回で同じ列を繰り返す不具合があったため、Math.random に替えてすべて再実行した。以下の数字は再実行後のもの。

**ルール案の比較(イベントなし、ランダムな誕生日の組み合わせ)**

| ルール | ていねい同士の誕生日決着 | 強い同士の誕生日決着 | 強いAIがていねいなAIに勝つ割合 |
|---|---|---|---|
| 4石を無くすだけ | 8±2% | 13±3% | 76±3% |
| 返す列を選べる(E1) | 26±3% | 21±3% | 85±2% |
| E1 + 1マス=数日(F1) | 約60% | 約60% | 約80% |
| E1 + F1 + 様子見の代償 | 63〜98%(距離による) | 68〜98% | 76〜89% |

試して採用しなかった案:
- 置き方の制限(隣にだけ置ける・挟めるなら必ず挟む): 効果は大きかったが、置き方は自由のままにしたいという要望により不採用。
- ±1日の切り札、様子見チケット、置いた石も1日、通り越したら動かない: 効果なし。
- 返した日数以内で好きなだけ動ける: 決着しやすすぎて、読みの差が出にくくなった。
- 石の重くなり方を速くする: 大きく飛びすぎて、かえって決着しにくくなった。
- 最大3回戦: 1試合が170手以上と長すぎた。

**イベント込み(本物のイベント表と暦、ていねい同士、300局)**

| ルール | 誕生日決着 | 誕生日が3か月以上離れた組 | 平均手数 | 1試合のイベント数 | 先手の勝率 |
|---|---|---|---|---|---|
| 4石を無くすだけ | 12±4% | 3±2% | 61 | 2.1 | 50±6% |
| E1 | 26±5% | 8±4% | 57 | 2.0 | 46±6% |
| E1 + F1 | 61±6% | 56±8% | 51 | 3.3 | 46±6% |
| E1 + F1 + 様子見の代償(採用) | 76±5% | 73±7% | 45 | 3.5 | 50±6% |
